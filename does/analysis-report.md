# 中海物业平台功能逆向分析

分析对象为当前账号登录的中海物业管理平台。已梳理 9 个模块、79 个可见功能入口及 285 条按钮权限定义，采集全部入口的初始页面 HTML、至少部分关联 JavaScript 和初始化请求。79 个入口对应 78 个不同菜单 URL；“报事”和“诉求管理”共用一个页面，但权限标识不同。另已补采星海图入口打开后的大屏，实际记录 8 个主要读取请求。目录范围由当前账号返回的菜单确定，不能代表其他角色或未接入的后台能力。

结论分为三类：页面与请求中实际观察到的事实、已加载源码中的分支和字段声明、需要后续证据确认的业务规则。页面 HTTP 200 不等于所有交互正常；源码里的接口字符串不等于该接口已执行。本轮没有提交新增、修改、删除、审批、支付、通知发送或后台同步操作。

## 主要实现机制

门户通过 `/portal/menu/queryMenu` 获取 `menuData`、`bnPriv` 和 `privageMap`。一级菜单按 `LEVEL_ID` 分组，子菜单通过 `PARENT_PRIVILEGE_ID` 关联，实际路由使用大写 `URL` 字段。页签按 `PRIVILEGE_CODE` 复用，当前活跃实现最多打开 10 个 iframe 页签；分析时逐页关闭前端页签，避免累积后台页面。

传统页面大量使用 jQuery、LigerUI、字典和组织/项目权限选择器。多数列表设置 `delayLoad=true`，打开页面只读取配置，选择查询条件后才请求业务列表；也存在初始化显式 `queryList` 的例外，不能统一认定未查询。接口与分页通常通过 `page/pagesize/startNum/pageSize` 等字段传递；各页面的具体契约见详细报告。

工单与待办不是单一 CRUD 列表：页面会按业务类型、任务状态、处理人和按钮权限选择派单、回访、审批或其他分支。例如待办的部分“详情/处理”点击可以先调用 `deleteWaitTask` 再跳转。源码里的这类行为已单列，不以“详情”的按钮名称认定只读，也没有为了采集执行这些分支。

报表指标有不同证据强度。例如“用户使用详情”的认证率确实在前端按认证数除以总数计算，并处理总数为零的情况；活跃度、员工指数、扫码报表等则直接展示后端字段。没有服务端材料时，不能自行替平台补出分母、及时阈值、去重或统计公式。

## 运行异常与缺口

全部 79 个菜单页面文档请求均返回 HTTP 200，但所加载资源和脚本仍存在异常。9 份模块场景记录了 129 条页面错误，其中 110 条与 Service Worker 注册状态有关，另 19 条涉及页面代码或响应解析；它们是采集环境中实际发生的错误，不等于已确认根因。

值得优先复查的是“用户管理”的非 JSON 权限响应，以及“消息通知”的 `/web-common/common/systemDataPermission` HTTP 510 和 HTML 非 JSON 解析错误。还记录了 39 条其他资源 404，主要是加载图片，另涉及样式和占位符脚本。27 条网络请求被中止；其中一部分可能与短暂等待后关闭页签有关，不能据此断定服务器故障。

原始模块证据中 38 个功能至少有一项关联脚本的该次响应正文未取得，共 381 条 script 响应正文不可用：380 条对应 HTTP 304 缓存响应，1 条对应 HTTP 404。这不能解释为丢失了 381 份不同代码。已经通过 REA 将可取得的 JavaScript 导出：859 次已验证导出、184 个不同内容 SHA-256，分别保留原始来源和摘要。逐页复核的已声明业务专用脚本没有发现正文缺失；该结论不涵盖未加载的后续页面或动态代码。共享库在其他事务中取得的正文仍不能改写某次 304 不可取得正文的事实，详见 [脚本可用性复核](script-availability-audit.md)。

原始场景的 `completeness` 为 incomplete，主要有未请求的事件族及响应正文缺口；事件丢弃计数为零不能把它改称完整。服务器源码、数据库模式、后台统计公式、其他角色菜单和未加载的后续编辑页面均不由这批材料证明。

## 已回答与仍待验证

| 问题 | 状态 | 证据范围 |
| --- | --- | --- |
| 当前账号有哪些功能、入口和按钮权限 | 已回答 | 9 模块、79 入口、285 权限定义 |
| 初始页面字段、路由、前端资源和初始化请求 | 已回答或部分回答 | 所有入口 HTML；逐项源码、缺口及 6 项独立动态界面观察 |
| 查询、分页、导出及业务操作怎样分流 | 部分回答 | 已加载源码可解释分支；实际执行证据限于页面初始化请求 |
| 全部筛选组合、导出文件、编辑/审批/删除/发送结果 | 未验证 | 需要相应测试数据、后续页面和受控业务操作 |
| 后台算法、SQL、数据库、完整权限 enforcement | 未回答 | 需要服务端源码、接口文档或额外后端证据 |

这份材料可作为前端功能清单、接口梳理和后续重建的依据。重建时应把“已观察行为”和“自行设计的实现”分开，尤其保留权限、业务状态迁移、金额和指标口径等未确认部分。
