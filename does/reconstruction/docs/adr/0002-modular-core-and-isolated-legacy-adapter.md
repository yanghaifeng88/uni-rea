# 模块化业务核心和独立旧系统适配

初期采用边界明确的模块化业务核心，使用一个可独立交付的后端应用承载主要业务模块，迁移任务与通知任务独立运行。旧系统字段、状态、私有接口和导出格式集中在适配层，新业务模块使用经业务确认的模型和契约。相比一开始拆分大量独立服务，这一选择使有限团队更容易完成事务、部署、故障处理和知识交接；代价是初期模块共享部署周期，需通过模块接口与数据归属约束防止耦合扩散。确有独立扩容、发布或团队责任需要的模块，再按已形成的边界拆分。

新系统新产生的数据独立落入公司控制的数据库和文件存储，旧数据库默认仅用于经授权的读取与迁移，不作为长期新业务写入库。语言、框架和数据库具体产品在资产摸底阶段依据维护团队能力、支持周期和部署条件确定。
