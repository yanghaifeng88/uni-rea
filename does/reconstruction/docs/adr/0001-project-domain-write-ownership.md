# 按项目和业务域切换唯一写入责任

旧系统源码不可修改，内部调用和所有客户端入口也尚未证实可控。方案以项目、业务域、单据来源组成明确的办理边界，而非随机分流同一笔业务；每张业务单据任一时刻只由一个系统办理。存量未结单默认继续在旧系统办结，切换后新单由新系统接收。相比两边自由修改或长期双写，该选择降低重复办理与状态冲突，但要求切换前验证全部入口可分流、旧写入可限制，并为旧待办保留可用入口。无法满足这些条件的范围只进行只读并行或延后切换。

新系统产生业务写入后，回退必须包含新增数据与外部副作用的处理；没有经过验证的旧系统回写路径时，以新系统版本回退、前向修复和可追踪人工办理维持业务。旧数据库不能充当自动覆盖新数据的恢复点。
