# 历史数据迁移与业务切换手册

手册适用于无供应商源码、旧系统仍承担业务的迁移。实际数据源和访问权限尚未核实，因此数据库、接口、导出和页面四条路径分别验收。默认保留旧未结单原办理责任；每批切换先确定范围和数据能力，再执行抽取、校验、发布与业务入口切换。

## 一 数据范围与获取证明

| 数据类 | 需要确认的内容 | 优先来源与特殊处理 |
| --- | --- | --- |
| 组织与项目 | 组织层级、项目及服务中心身份、编码和有效期间 | 公司主数据系统、旧只读库或授权接口；不要用同名组织自动合并 |
| 身份与权限 | 员工、账号、岗位、角色、项目范围、停用状态 | 与现有人员及统一认证来源核对；旧 285 条按钮定义仅作讨论起点，不直接授予新权限 |
| 客户与房产 | 客户身份、房产编号、楼栋单元、住户关系及历史变更 | 保留多房产、多客户、角色与期间；缺少历史关系时只迁已证实的当前关系 |
| 报事与工单 | event_id、work_id、来源、关联、状态、责任人、时间、处理和回访轨迹 | 当前列表可能只含最新状态；状态历史必须另取，无法取得则标明未知 |
| 投诉和品质 | 诉求原文、处理责任、期限、整改与回访、关联工单 | 保留原单据和证据，不把旧异常或超时统一转换为已完成 |
| 装修与访客 | 申请、审批、授权有效期、巡查、整改、通行结果 | 迁入历史不能激活门禁或电梯授权；正在生效的授权单独验证 |
| 费用与交易 | 费用明细、账期、币种、订单、渠道交易、代扣、退款、抵扣券、积分与发票 | 对账使用对应权威交易或财务资料；仅有汇总导出时保存报表档案，不伪造逐笔交易账本 |
| 内容与配置 | 公告、问卷、活动、模板、字典、设备配置、岗位和点位 | 保留版本与适用范围；过期问卷和已结束活动默认历史查询；设备密钥重新受控接入 |
| 附件与审计 | 图片、文书、录音、头像、附件关系、关键操作轨迹 | 列表 URL 不等于已拿到文件；实际下载、完整性与授权需单独核验 |

每一类记录可获取的时间范围、组织范围、包含和不包含的状态、是否含已删除记录、字段、关联和附件。保留控制总数的来源及获取时点。没有可信控制总数时，结果只能声明已取得范围，不能声明五年历史完整。

旧查询和导出的字段集合已有静态不一致证据。读取接口也不能仅按名称认定无副作用：部分待办详情可能修改待办，消息通知的源码还包含 queryAndUpdateMessage 候选。批量抽取只使用经过验证的读取、导出或副本访问路径，不用业务处理按钮代替读取。

## 二 三层保存与批次记录

### 原始保留区

保存原始备份、导出文件、授权接口返回或可得档案，以来源和批次隔离，限制读取权限。对象摘要、采集时间和来源证据独立保存，清洗或映射不能覆盖原始资料。原始敏感数据在受控数据环境中保存，不进入代码库或公共分析报告。

### 映射校验区

在隔离环境将原始字段映射为规范模型；保留旧字段和值，分类空值、重复、未知状态、无关联和解析失败。异常进入隔离表并有处置责任人，不能自动丢弃异常行后报告迁移成功。

### 新业务和历史查询区

为已确认可办理的主数据与业务对象生成新身份，为历史资料生成只读查询记录。导入标记、原始编号、来源批次和原始业务时间都可查。历史记录只展示已取得轨迹，不补造操作人、时间或审批意见；未知值与明确不存在分开显示。

每个批次至少记录以下字段：

| 字段 | 用途 |
| --- | --- |
| 批次编号与转换版本 | 重跑、比对和审计 |
| 来源系统和身份范围 | 区分不同系统、租户、业务实体和项目编号空间 |
| 抽取区间及截止点 | 固定时间、组织和状态范围 |
| 来源位置或接口及字段名 | 保存路径和读取契约，认证值另行受控管理 |
| 原始记录数与控制数 | 确认覆盖率，标记控制数是否可信 |
| 已导入数与隔离数 | 使源范围内记录有去向；重叠批次和去重记录另列 |
| 摘要与附件清单 | 验证文件和复制完整性 |
| 字典和身份映射版本 | 解释业务含义与关系 |
| 增量游标与最后完成时点 | 续跑、迟到数据和同步延迟 |
| 校验结果与处置记录 | 逐项差异、负责人和发布条件 |

## 三 身份关联与转换规则

建议保留旧身份映射：来源系统、来源身份范围、实体类型、旧编号、新编号、来源批次、有效期间及映射版本。只有核实旧编号全局唯一后才能简化范围；否则报事、工单、客户、账号、组织和支付等各自使用合适的身份空间。

1. 旧编号按原始形式保存，防止大整数精度损失、前导零丢失或跨项目碰撞。电话、姓名、展示房号都不直接作为唯一键。
2. 同一来源实体重跑更新对应迁移对象，不重新生成一份；原始版本仍保留。真实业务重复与采集重叠分开处理。
3. 日期保留原始文字和解析时区。只含日期的字段不自动补成精确操作时刻；Asia/Shanghai 是方案业务讨论时区，不替代源数据时区证据。
4. 金额保留币种和批准精度，以精确数值转换。未知币种、单位、含税定义或符号进入异常处置，不用猜测的除法修正。
5. 字典同时保存旧 code、旧标签和新归一值。未知 code 保留为未映射；默认值不得改变历史已完成、撤销、作废或审批结果。
6. 附件保存业务对象、新旧附件身份、原始文件名、大小、内容摘要和复制结果。只有签名 URL 时，需要在授权有效期内取得实际字节；失效 URL 不算已迁文件。
7. 密码和旧会话不作为可直接复用的数据。通过公司统一认证或新账号激活恢复登录，历史操作人依然可追溯到旧账号身份。
8. 历史导入走独立导入通道，不执行普通创建单据后的通知、扣款、发券、开票或设备指令。自动任务按来源和导入状态隔离。

典型核验场景包括同一客户多个房产、同房产多位住户、员工跨项目调动、组织改名、同一报事关联多个执行工单、工单重派、附件缺失、未知状态与支付已成功但回调迟到。具体基数和规则由业务确认，不按旧界面展示方式猜测。

## 四 全量与增量获取

| 来源 | 全量基线 | 增量处理与限制 |
| --- | --- | --- |
| 数据库副本或备份 | 使用可说明一致性时点的备份或副本，在隔离环境抽取 | 具备授权和日志保留条件时读取变更；否则按可信更新时间重取并对账；删除要有独立识别方式 |
| 授权接口 | 固定范围和截止点，使用稳定排序及分页，保留全部原始批次 | 优先以更新时间和游标读取，重叠窗口去重；若只有创建时间，不能捕获全部修改，需周期重扫和删除核对 |
| 导出文件 | 分项目和期间导出，检查行数上限、隐藏筛选及附件能力 | 重复导出可重叠期间并比对差异；已导出期内的旧数据仍可能修改，须单独重扫 |
| 页面采集 | 定义可见页面、角色和范围，限制并发并观察生产影响 | 页码变化可能漏行或重复；无稳定顺序和变化标识时不能证明无漏增量，仅可作为受限归档 |

同步时先明确来源的一致性能力。接口不提供一致快照时，使用时间界限、重复扫描、去重和独立对账减少漂移；若修改或删除仍无法观察，记录残余差异并保留旧查询，不能宣称建立了与数据库复制相同的一致性。

在业务办理切换前，旧业务域是对应数据的唯一权威来源；新库是读取副本。切换后新单归新系统，旧未结单仍按原系统身份持续同步查询。主数据维护单独移交责任，不随着工单试点自动切换。

旧接口限流、导出容量和登录有效期要测量。作业应支持限速、断点续跑、可重试错误、批次停止和告警；读取失败后不得使用未完成批次覆盖已经发布的历史数据。

## 五 数据验收门槛

| 校验项 | 核验方法 | 发布条件 |
| --- | --- | --- |
| 范围与数量 | 按项目、年份或期间、实体和状态分组，对照可信控制数 | 迁移范围内每条源记录均有导入或明确隔离去向；范围差异解释完成 |
| 身份与关联 | 校验来源映射、客户房产、事件工单、附件归属等 | 当前办理必需身份和关系无未处理缺口；非关键历史缺口逐项获准并可见 |
| 未结业务 | 逐单核对状态、责任人、办理系统和入口 | 范围内全部未结单都有有效办理路径，任何单据不能两边同时办 |
| 资金与票据 | 按币种、期间、项目、交易状态逐组及逐笔核验 | 无未解释金额差异；旧票据和交易身份保留；历史导入副作用为零 |
| 附件 | 业务关系、数量、大小、摘要与可打开性 | 关键办理附件完整；历史缺失有原始情况和处置清单 |
| 字典与时间 | 检查未知状态、日期和时区、原始时间精度 | 未知状态不得进入可执行流程；关键排序、期限和账期解析明确 |
| 权限 | 按角色和项目验证查询、附件、导出 | 受限数据不可被范围外用户读取或批量导出 |
| 重跑 | 同批重跑及断点恢复，比较身份与数量 | 不增加重复对象，隔离及回退记录保留，已发布批次不被半成品替换 |

差异为零指批准迁移范围中的关键业务和资金差异为零，不是忽略无法取得记录后的统计百分比。对无法证明覆盖的历史，应先标明限制，再由业务决定能否作为档案发布；这不允许以缺口历史支撑未经核验的收费或审批。

## 六 每批切换操作顺序

批次按项目、业务域、渠道和单据归属确定。准备时把计划起止时间、实际时间、负责人、结果和恢复条件填入本表，至少进行两次同范围演练。旧未结单继续办理与新单入口冻结需要不同策略，避免为切换一个模块锁住全平台。

| 时点 | 责任人 | 动作与核验 | 失败处理 |
| --- | --- | --- | --- |
| T 前 7 天 | 业务与技术负责人 | 确定批次、全部入口、旧未结单、外部依赖和候选切换窗口；通知相关办理人员 | 入口遗漏或旧服务条件不满足则延后 |
| T 前 3 天 | 数据负责人 | 完成全量基线和至少一轮增量，产出数量、身份、状态、附件及金额对账 | 未处理关键差异不得进入切换 |
| T 前 1 天 | 测试及运维 | 验证部署和恢复、越权、回调去重、备用受理；确认人员值守及可用容量 | 没有可恢复备份或备用受理则停止 |
| T 前 30 分钟 | 业务负责人 | 保存旧未结单清单，说明两系统单据归属；确认旧单仍可办理 | 保持旧受理并取消本批切换 |
| T 时点 | 入口及集成负责人 | 限制本范围旧新建入口，检查 APP、小程序、后台、呼叫中心、定时任务和回调；开启已演练的暂存受理，新业务办理在发布验收后启用 | 无法形成唯一新建入口则不启用新系统办理写入 |
| T 最终同步 | 数据负责人 | 在源能力允许的边界内完成最终增量和对账，保存截止点及发布批次 | 新系统无业务写入时恢复旧受理；有受理暂存则先核对暂存清单 |
| T 发布 | 运维与业务负责人 | 原子发布该批次映射和规则，开启新办理；外部通知只走当前业务责任系统 | 使用已验证的版本回退或前向修复方案 |
| T 后 15 分钟 | 业务与测试 | 验证受理、派单、权限、附件与通知；逐单核对实际确认的新请求 | 出现丢单、重复或越权时停止扩大范围，隔离相应处理 |
| T 后 2 小时 | 运维及数据负责人 | 查看业务错误、积压、对账、接口延迟和外部回调 | 守住受理路径并处理异常队列，不盲目重新提交外部动作 |
| T 后 1 天 | 项目负责人 | 新旧单据清单和现场办理复核，形成日结与遗留问题 | 未处理问题阻止扩大项目数量 |
| T 后约 2 周 | 业务及技术负责人 | 检查稳定运行、容量和连续对账，确定下一批 | 未达到验收目标则继续当前试点 |

切换可以配置低峰窗口，但关键受理通道继续可用。若只有人工限定入口、不能控制旧客户端或无法确定最后增量，则不宣称技术上的不停机迁移；保持旧系统承担相应业务，新系统只读验证或独立小范围办理。

## 七 有新数据后的恢复

### 可以恢复旧入口的情况

没有新业务写入时，恢复旧入口和对应受理配置，保留迁移批次记录。已有暂存受理请求时，先按照唯一受理身份确认它们尚未进入外部办理，再以经过验证的方法交付给一个办理系统；交接完成前不能丢弃暂存清单。

### 默认恢复新系统的情况

新系统已产生新单据后，优先回退应用版本并保留新数据库，或暂停后续动作进行前向修复。数据库变更需支持前一稳定应用版本；难以反向转换的结构变更延后到稳定期完成。故障期间如采用人工办理，也要沿用新单号、责任人和结果记录，恢复后补录到同一权威记录。

新旧系统业务结构不同，数据库备份不能直接互换。没有源码、可验证导入接口和重放演练时，旧库通常不包含这些新单据，因此不能把“把流量切回旧入口”当作完整恢复。

### 已发生外部动作的情况

消息、扣款、发票、设备指令的结果向对应渠道核实，保存请求身份、外部流水、结果及处置。网络超时不等于外部失败；先查询结果再决定重试。资金、票据或设备的纠正按对应业务规则和责任人操作，迁移程序不能通过重导历史或回滚数据库隐式触发纠正。

## 八 历史查询和旧系统退出

历史查询应显示旧单号、来源、业务期间、归档时点、当前数据质量和可得附件。旧口径报表以原快照及口径说明保留，新口径报表标明版本；需要跨新旧比较时明确数据起止范围和计算规则，不能直接拼接相同标题的数字。

旧服务停止前核验所有未结单、客户入口、二维码、APP 旧版本、支付或设备回调、自动任务、报表及附件链接。仍需原设备平台或未迁回调的模块，明确其继续服务期限或替代方案；不能因为浏览器菜单已迁完就关闭供应商系统。

原始档案存储和历史查询必须能在供应商停止服务后独立运行。保留期限、访问范围、删除或封存规则由公司业务及数据管理要求决定。最终验收包括在独立环境恢复数据库和附件、按原单号查到档案、处理遗留单据，并确认停止旧服务不会再产生待处理交易或失联业务。
